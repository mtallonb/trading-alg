# trading-alg

Personal Kraken/eToro trading scripts (EUR): read balance, orders and trades, rank assets, suggest or cancel orders.

## Running

- `poetry run python menu.py` (Python 3.11) launches each `src/` script as a subprocess, from the repo root (`./data/...` paths, `src/` on path).
- **Never run `src/orders.py` without asking**: it uses real Kraken keys (`data/keys/kraken.key`) and, with `AUTO_CANCEL_*_ORDER = True`, cancels real orders after an `input()`.
- Safe checks: `python3 -m py_compile src/orders.py`; `poetry run python -c "import sys; sys.path.insert(0, 'src'); import orders"` (import has no side effects).
- `src/summary_trades.py` reads Kraken `TradesHistory` with real keys and appends to `trades_2026.csv`: don't run `main()` (not even with a fake Kraken, it writes the real CSV); test by importing it and calling `fetch_new_trades` with `FakeKraken` or `compute_gain_loss`/`compute_pair_gains` on the CSV read with `read_trades_csv`.
- Tests: `poetry run pytest` (pytest is a dev dependency; `pythonpath` = `src`, `tests`). Code that talks to Kraken is tested with `tests/fake_kraken.py` `FakeKraken` (same interface as `krakenex.API`, no keys or network: `TradesHistory`/`Ledgers` with `start`/`end`/`ofs`/`limit`/`count`, `OpenOrders`, `Balance`, `Ticker`, `Earn/Allocations`, `OHLC`, `CancelOrder`, errors queued with `queue_error(after=...)` also mid-pagination, calls logged in `calls`); pass it as `kapi=`. Add a test for every bug fixed. Tests must not touch `data/`: use `tmp_path` + `monkeypatch` for file constants, and set `orders.LOAD_ALL_CLOSE_PRICES = False` (`read_prices_from_local_file` writes a prices file when missing).
- ruff is not installed; config in `ruff.toml`.

## Layout

- `src/utils/basic.py`: helpers (paginated Kraken, trades CSV, ranking, tables, rounding, prices: `read_prices_from_local_file` returns empty for a pair with no local file, `update_asset_prices` downloads/extends it; `is_eur_pair` = pair quoted in EUR). `src/utils/classes.py`: `Asset`, `Order`, `Trade`, `MAPPING_NAMES`, `OP_BUY`/`OP_SELL`. `src/backends/`: `kraken.py`, `etoro.py`.
- `data/`: daily prices/volumes per asset, `trades_2026.csv`, smart summary outputs. `src/config.env` and `*.key` are gitignored.
- `src/orders.py`: UPPER_CASE config constants at top; one function per phase (`build_assets` → `fill_prices_and_volumes` → `fill_staking_info` → `fill_orders` → `fill_trades` → `remove_assets_without_trades` → `build_ranking_rows` → `compute_and_print_ranking` → `print_orders_proximity` → `print_orders_to_create` → `print_cash_summary` → `print_time_summary`, plus `print_last_trades`); `main()` only orchestrates, no module-level state. Timing via `with timer(timings=..., label=...)`; shown labels/order in `TIME_SUMMARY_LABELS`, missing phases print `skipped`. `Tee` copies stdout into `captured_output` for the smart summary.
- `src/summary_trades.py`: yearly G/L per pair (FIFO/LIFO) from the trades CSV plus new Kraken trades. `main()` → `read_trades_csv` → `fetch_new_trades` → `compute_pair_gains` (calls `compute_gain_loss(method=FIFO|LIFO)` per pair) → `print_summary` → `print_pair_gains` → `append_trades_to_csv`.

## Kraken REST API

- Docs: https://docs.kraken.com/api-reference/ (e.g. `account-data/get-open-orders`, `account-data/get-trades-history`, `market-data/get-ticker-information`). Check them before assuming response formats or limits.
- Used via `krakenex` (`kapi.query_private`/`query_public`); paginated in `get_paginated_response_from_kraken`: `ofs` advances by the records received (no `limit` sent, Ledgers ignores it), `pages=None` reads until `count`/an empty page, rate limit errors retried (`KRAKEN_RATE_LIMIT_RETRIES`/`_WAIT`), other errors raise `KrakenError` (never return partial pages: they'd be the newest records only and leave a gap in the CSV).
- `OpenOrders`: `result.open` is a dict keyed by txid and the docs say nothing about its order, so sort by `opentm` when it matters (`oldest_order`).
- `TradesHistory`: `result.trades` dict keyed by txid, most recent first by default; `limit` 50 by default (max 100), `ofs` offset, `start`/`end` unix timestamp or txid (`start` exclusive, `end` inclusive), so `start` = last CSV trade time reads only the new trades.
- `Ticker`: an unknown/delisted pair (e.g. `ETHWEUR`, `LUNA2EUR`) returns `EQuery:Unknown asset pair` together with the known pairs' `result` (verified on the public API); the error doesn't name the pair, so `fill_prices_and_volumes` names the assets left without price. It can also come back with no `result` at all (seen with `EURUSDEUR` from an open `EURUSD` order), which raises `KrakenError`.
- `EURUSD` (USD per EUR; base EUR, so `vol` in EUR and `price`/`cost`/`fee` in USD): its `OHLC` comes under `ZEURZUSD` (`RENAME_ASSET_MAPPING`). xStocks (`AAPLxUSD`, quoted in USD) need `asset_class=tokenized_asset`; only `GOOGLxUSD` held, excluded everywhere. Real US stocks (to be bought with the USD) are not in the documented REST API: check `Balance`/`OpenOrders`/`TradesHistory` once there is one.
- `OHLC`: no pagination; at most the 720 most recent candles whatever `since` is (~2 years daily), last one not yet closed. `get_new_prices` prints `OHLC GAP` when the first candle starts more than a day after `since`.
- `src/volumes.py` runs on import (no `main()`): don't import it in tests.
- `src/prices.py`: updates the local daily prices of `PAIRS` (`EURUSD`, `GOOGLxUSD`; xStocks `OHLC` sent with `asset_class=tokenized_asset`, `is_xstock_pair`) with `update_asset_prices` (public `OHLC`, no keys; writes `data/prices_with_volume/`).

## Conventions

- **Always pass keyword arguments** to project functions/methods (`fill_orders(open_orders=open_orders, assets_dict=assets_dict)`); not for builtins, pandas, `str` methods or `*args` (`Tee`).
- 120-char lines, trailing commas in multi-line calls (ruff `COM`), quotes preserved (mostly single). Comments always in English (older ones are still mixed with Spanish; translate them when touching that code).
- Delete unused variables/constants.
- Refactors preserve behavior: move code as-is, diff against `HEAD` ignoring indentation; fix bugs in separate steps.
